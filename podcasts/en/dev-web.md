*Written summary of the episode. The audio is produced by NotebookLM from the
learning path itself; this text is therefore not a word-for-word transcript,
it says the same thing in fewer words.*

**First, a web page is built like a house.** One language frames the walls,
another paints them, and a scripting language brings the plumbing and the
electricity. The golden rule: design for the smallest phone screen first — the
lack of space forces you to keep only what matters.

**Second, an application runs like a restaurant.** It needs a strict contract for
how the kitchen and the waiters talk, a filing cabinet to store the data, and a
way for several cooks to change the recipes without overwriting each other. And a
slow page is rarely a slow server: it is almost always too many round trips.

**Finally, what makes a site last** is performance, by keeping ready-made copies
of files; security, by treating everything that comes from outside as hostile;
and tests, which let you change code without fear. Technical debt works like a
loan: cutting corners buys time today, and the interest is paid in hours lost to
bugs.

This path is education, not personal advice. A good website rests on solid
foundations and debts paid back, not on the latest tool.
